# Development guide

Working conventions for this repository. Progress is tracked in
`docs/EXECUTION_PLAN.md`; this file holds the rules that do not change
from task to task.

## Authority

`docs/PROJECT_SPEC.md` is authoritative. `docs/ROADMAP.md` sequences the
work and defines the gates. `docs/EXECUTION_PLAN.md` tracks what is done.
Where documents disagree, the spec wins.

`docs/methodology.md` holds the rules that shape every number: physical
capture supplies quantity only and price comes from the US snapshot;
SKU identity is verified by barcode or flagged; capture lists are
pre-registered before any size is read. Read it before touching capture
or unit-price code.

A phase is not complete until its gate is met. Do not start the next
phase early.

## Environment

Python 3.13, virtual environment at `.venv/`.

PowerShell (Windows):

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned -Force
    .venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    pytest

Bash / macOS / Linux:

    source .venv/bin/activate
    pip install -r requirements.txt
    pytest

Activate the environment rather than calling the interpreter path
directly. Windows PowerShell 5.1 chains commands with `;`, not `&&`.

`requirements.txt` carries Phase 1 dependencies only. Later phases add
their own (stats in Phase 2, embeddings in Phase 3, Streamlit in
Phase 4) when that phase starts, not before.

## Git workflow

After every completed step — a file created, a config populated, a
function written, a test passing, a doc section finished — commit and
push immediately:

    git add -A
    git commit -m "<type>: <what changed>"
    git push

Do not batch. Small and frequent, always pushed.

Types: `feat`, `fix`, `data`, `docs`, `test`, `refactor`, `chore`,
`analysis`. One logical change per commit. Never bundle unrelated work.
Never commit files matched by `.gitignore`.

Commit messages describe the change only. No trailers, no footers, no
"generated by" lines. All commits author as the configured git user.

## README discipline

README.md is refreshed at every GATE from measured figures only.
Any push touching README.md requires
`Select-String -Path README.md -Pattern "\{\{"` to return nothing.
Findings are stated with their caveats in the same paragraph, never
deferred to a limitations section.

## Hazards discovered in Stage 1.0

Recorded here because they are easy to forget and expensive to repeat.

- **Shopify `variants[].grams` is shipping weight, not net content.** It
  is populated on 55.7% of products probed — over 4x real size coverage —
  and would yield plausible, uniformly wrong price-per-unit figures. Never
  use it as quantity. Enforced in `config/unit_rules.yaml`.
- **robots.txt is not permission.** Ulta permits product pages to every
  crawler and prohibits collecting listings and prices in its terms. Check
  both; the terms govern.
- **Regex on raw HTML fabricates coverage.** A first pass matched `029g`,
  `0MG`, `7G` inside minified scripts and reported 18/21 pages with size.
  Strict measurement on visible text gave 2/21. Strip scripts, require a
  plausible magnitude, and report the method alongside the number.

## Anti-goals

Do not: fabricate data · convert g↔mL · use price for tier or
similarity · scrape prohibited sources · report p-values without effect
sizes · over-engineer · add tools that don't earn their place.

Never print API keys or full request URLs in notebook cells. Clear
notebook outputs before committing anything under `notebooks/`.
